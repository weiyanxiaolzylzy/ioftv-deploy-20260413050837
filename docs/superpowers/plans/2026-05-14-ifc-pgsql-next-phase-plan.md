# IFC 持久化与查看器优化计划

> 当前版本为项目阶段计划，面向开发推进与进度汇报使用。

## 目标

将当前系统从“可演示的 IFC 查看与构件提取”推进到“可持续使用的项目级 IFC 管理平台”：

- IFC 构件数据稳定按实例入库
- 构件详情统一从后端数据库读取
- 页面切换时 IFC 查看器尽量常驻，减少重复加载
- 主页面统计数据开始和数据库联动

## 当前已完成

### 1. IFC 主链路

- 已完成 IFC 上传与查看器加载
- 已完成构件编号提取
- 已完成后端 IFC 构件同步入库
- 已完成 PostgreSQL 接入
- 已完成详情查询从按 `componentMark` 回退，改为按 `expressID` 实例优先

### 2. 数据库主链路

- 已完成 PostgreSQL 运行接入
- 已完成班组、标兵、排名、今日计划等基础接口的 PG 兼容
- 已完成测试阶段空数据接口稳定返回，避免 `500`
- 已完成 `data.json` / SQLite 从运行主链路退出

### 3. 当前问题

- 旧项目数据仍可能带有旧逻辑写入结果，需要重新同步 IFC 修正
- IFC 页面切换或整页刷新后仍需重新加载，体验较慢
- 主页面统计数据尚未完全与构件状态、班组、项目数据联动

## 下一阶段计划

### 第一阶段：修正现有 IFC 项目数据

目标：让当前项目中的相同构件编号但不同位置的实例，能够正确区分并展示自己的详情。

计划内容：

- 对当前项目重新执行 IFC 同步
- 用新逻辑覆盖旧逻辑写入的构件详情
- 抽查多个“相同构件编号、不同位置”的实例
- 确认位置编码、标高、长度、主规格、主零件编号等信息是否按实例区分

完成标准：

- 同编号不同位置构件不再显示完全相同的详情
- 点击单个构件时，后端按 `expressID` 返回实例级详情

### 第二阶段：查看器常驻与切页优化

目标：减少页面切换时 IFC 查看器重复初始化和模型重复加载的问题。

计划内容：

- 将 IFC 查看器改为全局常驻组件或全局 iframe 容器
- 页面切换时只隐藏/显示，不销毁查看器实例
- 保留当前项目、当前 IFC URL、当前选中构件状态
- 切回页面时直接恢复当前模型与选中状态

完成标准：

- 页面切换后 IFC 不需要重新从零加载
- 返回 IFC 页面时可快速恢复上次项目和选中状态

说明：

- 浏览器整页刷新 `F5` 后无法做到完全不加载
- 但可以做到自动恢复项目、自动恢复 IFC URL、减少重复同步与重复详情解析

### 第三阶段：构件详情数据库化彻底收口

目标：构件详情优先从数据库读取，避免每次点击构件都重新解析 IFC 原始属性。

计划内容：

- 导入 IFC 时尽量将现阶段需要展示的字段一次性入库
- 点击构件时优先读数据库详情
- 数据库缺失时再回退到 IFC 原始属性
- 梳理当前真实可提取字段与暂时为空字段

当前重点字段：

- 构件编号
- 位置编码
- 下标高
- 上标高
- 长度
- 宽度
- 面积
- 构件重量
- 净重
- 毛重
- 材质
- 主规格
- 主零件编号

完成标准：

- 点击构件详情时主要字段直接来自数据库
- IFC 前端临时解析仅作为补充或兜底

### 第四阶段：主页统计数据入库与联动

目标：让主页面展示的项目数量、构件数量、班组信息、合格率等指标有稳定数据库来源。

计划内容：

- 明确主页统计项的数据来源
- 将项目、构件、班组、检测状态、合格率建立稳定统计关系
- 统一从 PostgreSQL 查询主页展示数据
- 班组和相关人员信息以“项目构件管理”中的班组配置为准

拟联动数据：

- 项目数量
- 构件数量
- 检测中数量
- 已完成数量
- 不合格数量
- 班组数量
- 装配/检测合格率
- 标兵班组
- 排名数据

绩效榜统计口径：

- 按班组合格率排序
- 合格率 = 已完成 / （已完成 + 不合格）
- `待检测`、`检测中` 不计入合格率分母
- 排名第一排序字段：合格率降序
- 排名第二排序字段：已检测数（已完成 + 不合格）降序
- 排名第三排序字段：班组名称正序
- 标兵班组默认取当前排名第一的班组

完成标准：

- 主页面主要统计项不再依赖静态假数据
- 统计项和构件状态、班组配置保持一致

### 第五阶段：生产环境存储与部署整理

目标：为后续服务器部署准备稳定的数据存储结构。

计划内容：

- PostgreSQL 继续作为业务数据库
- IFC 文件继续存磁盘目录或后续切换到 MinIO
- 数据库存储 IFC 元信息与构件详情，不直接存大 IFC 文件本体
- 整理测试环境与生产环境配置项

建议方案：

- PostgreSQL：存项目、构件、班组、状态、统计数据
- 文件系统 / MinIO：存 IFC 文件、班组图片、质检附件

## 优先级

### P1

- 重新同步当前项目 IFC 数据
- 修正旧项目中实例级详情混用问题

### P2

- IFC 查看器常驻
- 页面切换不重载

### P3

- 构件详情字段进一步数据库化
- 主页面统计数据联动数据库

### P4

- 生产环境文件存储整理
- MinIO / 部署结构优化

## 当前建议执行顺序

1. 先对当前项目重新同步 IFC，确认实例级详情问题是否彻底解决
2. 再做 IFC 查看器常驻，解决切页慢的问题
3. 然后完善主页面统计数据与班组联动
4. 最后整理生产环境部署与文件存储

## 备注

- 当前系统已经基本完成“IFC 上传、查看、构件编号提取、构件入库、详情查询”的主链路
- 现阶段主要工作已从“能不能做”转向“数据是否稳定、体验是否流畅、统计是否统一”
- 后续每一阶段都应尽量避免再回到按 `componentMark` 进行唯一匹配的旧逻辑，统一坚持实例优先
